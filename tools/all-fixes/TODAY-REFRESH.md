# Maintained source refresh

The previous public source baseline, original release refs and validated image
remain immutable. This refresh has distinct feature/candidate refs and evidence.
It is source reconstruction, not a new binary, ABI or hardware certification.

The default source selection adds the accepted Python shutdown API repair,
generic opt-in JVC VSIF kernel/UI support, and matching native Ethernet
HTTPS10/UX11 runtime plus incremental settings UI. Existing sticky-SDR GUI,
seamless-gate and Ethernet8a changes are retained once, not replayed as lab fixes.
The manifest pins every selected source and its dependencies.

Kernel suppression compiles Off, while the existing seamless gate compiles On.
The independent Kodi suppression setting defaults Off and adopts verified
kernel state once without overriding a saved On; later saved choices remain
owned by the user. Rebuild `kodi.bin`, `system/settings/settings.xml` and
English `strings.po` together. Old lab overlay/stock binaries and assets are not
substitutes for this integrated tree.

HDR10+ conversion is existing code with an existing configuration toggle.
The hidden mapping's visibility diagnosis is unresolved and excluded; no
visibility repair or configuration migration is shipped. Pending preroll,
silenceES, VFM/parser/decoder experiments and runtime experiment configurations
are excluded.

Native and settings updates form a matching source pair. Settings starts at its
sealed integrated8a snapshot and replays only the incremental addon deltas;
the full platform001 patch is not applied to that snapshot again. Three prior
distribution translation corrections remain intact. Native recipes, original
service units, canonical six component bindings and the two-unit LF installation
adapter remain unchanged.

HTTPS selection remains explicitly experimental at runtime: provider permission,
quota and fleet reliability are unresolved. Its 10Mbps pacing refers to
application reads, not an exact server/wire cap or gigabit certification. UX11
manual/nonvisual acceptance does not establish visual/readability, live receive,
inflight Cancel, fresh calibration, cold boot or suspend acceptance.
Preserve genuine existing LAN/HTTPS and manual profiles, protected history and
user choices. Do not seed index30, copy device profiles, eagerly migrate schemas
or generate boot verification traffic.

Jellyfin remains a user-installed addon, with a source-only identified companion
under `companions/jellyfin-late-keepalive`. A normal SYSTEM/kernel upgrade
preserves existing repaired addon code and `addon_data`. There is no accepted
automatic repair hook or complete pinned addon package for fresh/unfixed
installations. The companion contract requires separate authorization and exact
identity/source gates; it never changes addon versions/dependencies or suppresses
the addon updater.

The Python API repair belongs in the rebuilt Kodi SYSTEM. During separately
authorized installation, retire its exact old identity-guarded owned overlay
while Kodi is quiescent, preserve recovery material and record the transition.
Never weaken old guards to admit a historical binary on the new cohort.

Only the parent performs publication, firmware builds and authorized tar
packaging in its new private SDK/output. Every build uses
`PROJECT=Amlogic-ce DEVICE=Amlogic-ng ARCH=arm` and the verified materialized
six source bindings. Kernel, modules/DTs, Kodi and system assets require fresh
cohort checks before any installation; historical config/exports and a matching
three-file Ethernet ABI check do not establish binary-wide equivalence.
